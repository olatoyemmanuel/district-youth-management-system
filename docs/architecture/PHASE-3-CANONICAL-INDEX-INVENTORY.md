## 1. Purpose

This is the Phase 3 canonical named-index inventory. It reconciles the Phase 2 index catalogue with the revised DDD-013 physical slice, ODR-004 owner-approved scope defaults, TBR-01 attendance and appointment mechanisms, category eligibility provenance, reporting data ownership and the new composite scope relationships.

Primary-key indexes generated by PostgreSQL are not listed unless they are also named candidate keys required by composite foreign keys. Every index must be verified against its exact predicate, ordered key columns, FK support role and expected query workload before DDL approval.

## 5. DDD-013 index contracts

- Authenticated identity unique index: `actor_user_account_id, operation_code, scope_fingerprint, COALESCE(session_id, reserved-zero-uuid), key_digest`, partial where `scope_mode='AUTHENTICATED'`.
- Pre-auth identity unique index: `pre_auth_context_id, operation_code, scope_fingerprint, key_digest`, partial where `scope_mode='PRE_AUTHENTICATION'`.
- Request fingerprint is deliberately excluded from uniqueness. Same identity/different fingerprint returns HTTP 409 `IDEMPOTENCY_KEY_REUSED`.
- A CHECK rejects the reserved zero UUID as an actual session ID.
- `ix_idempotency_records_session_actor` supports the composite session-owner FK. Actor and pre-auth FKs are supported by the leading tuples of their respective partial identity indexes or the actor workload index.
- Recovery claim uniqueness applies only to `event_type='CLAIMED'`; the general recovery-event FK uses a separate non-partial index.
- Pre-auth secret digest uniqueness is partial because the digest is erased after the 10-minute context lifetime while the context identity row remains for tombstone references.

## 6. Organizational scope and reporting indexes

- Departments are district-owned. Church-specific department-code and church-owner indexes are removed.
- Events are district-bound; optional `church_id` identifies a church owner and is bound to the same district by a composite FK.
- Event organizer associations use composite source indexes matching `(event_id,district_id)` and `(department_id,district_id)`.
- Report runs require district scope and support optional same-district church or department scope. GLOBAL report scope is excluded.
- `uq_departments_id_district` and `uq_events_id_district` are target candidate keys for composite FKs.

## 7. Policy-blocked indexes

The six existing policy blockers remain blocked:
- current church membership uniqueness, ODR-002 lifecycle predicate;
- open church transfer uniqueness, ODR-002;
- current department membership uniqueness, ODR-007;
- current event registration uniqueness, ODR-008;
- current member category assignment uniqueness, ODR-001;
- normalized email uniqueness, identifier normalization decision.

Do not invent state predicates or activate these indexes until the relevant authority decisions and lifecycle vocabularies are approved.

## 8. Redundancy and query-plan review

The Phase 3 candidate removes redundant FK support indexes where a suitable left-prefix unique/workload index now covers the relationship. This is a structural design assessment only. Query-plan and workload validation remain pending until the production PostgreSQL provider, collation and environment are confirmed under ODR-ENV-001–007.
